# Internet Archive API Implementation Guide for Codex

Target: implement robust code that can browse Internet Archive collections, enumerate item identifiers, inspect item metadata, and download files.

This document assumes a Python implementation, but the HTTP API details are language-agnostic.

Verification status: checked against the current Internet Archive Developer Portal and Search Help on 2026-05-18.

Current-compatibility notes added in this enriched version:

- The current cursor/deep enumeration endpoint is verified as `https://archive.org/services/search/v1/scrape`.
- Metadata Read still uses `GET https://archive.org/metadata/{identifier}` and partial reads are wrapped in a `{"result": ...}` response.
- Automated tools must send a descriptive `User-Agent`; the current IA bot guidance explicitly requires tool name and version, and asks AI agents to identify the model when applicable.
- Archival download URLs under `https://archive.org/download/...` remain the stable form; redirected `iaNNNNNN.us.archive.org` machine URLs must not be stored as permalinks.
- The `internetarchive` Python library and `ia` CLI are current first-party tools, but direct HTTP is still the better fit for tightly controlled crawlers and UFID-style fixity ingestion.

---

## 1. Mental Model

Internet Archive content is organized around **items**.

An **item** is a logical unit with:
- a globally unique `identifier`
- item-level metadata
- zero or more files
- file-level metadata
- optional derivative files generated by Internet Archive
- membership in one or more collections

A **collection** is also an Internet Archive item, but with special collection behavior. In metadata/search it is represented as an item whose `mediatype` is usually:

```text
collection
```

Important: collections are **not strict folders**. They are metadata-based groupings. An item can belong to multiple collections. Treat the structure as a graph, not a filesystem tree.

## 3. Identifiers

Every item has a unique `identifier`.

Current IA identifier rules:

- ASCII alphanumeric characters, underscore, dash, and period are allowed.
- The first character must be alphanumeric.
- Maximum length is 100 characters; IA recommends roughly 5-80 characters.
- Identifiers are globally unique across archive.org, not just within a collection.
- Once assigned, an identifier is not meant to change.

Given:

```text
IDENTIFIER = xfetch
```

The canonical URLs are:

```text
Details page:
https://archive.org/details/xfetch

Metadata JSON:
https://archive.org/metadata/xfetch

Download directory:
https://archive.org/download/xfetch

Specific file:
https://archive.org/download/xfetch/<filename>
```

Do not store redirected machine-specific URLs such as:

```text
https://ia802304.us.archive.org/...
```

Use archival URLs under:

```text
https://archive.org/download/<identifier>/<filename>
```

Reason: Internet Archive moves items between storage servers.

Implementation note: identifiers are not arbitrary URLs. Validate them before building URLs. Do not accept slashes in identifiers; slashes belong only in file names/paths below `/download/{identifier}/`.

## 4. Metadata API

### 4.1 Full metadata request

Endpoint:

```http
GET https://archive.org/metadata/{identifier}
```

Example:

```http
GET https://archive.org/metadata/xfetch
```

Expected response: JSON object containing fields such as:

```json
{
  "created": 1616004182,
  "d1": "ia600308.us.archive.org",
  "d2": "ia800308.us.archive.org",
  "dir": "/21/items/xfetch",
  "files": [
    {
      "name": "xfetch.pdf",
      "source": "original",
      "format": "Text PDF",
      "mtime": "1479169618",
      "size": "419170",
      "md5": "ee68c235c2cfc1007a5ab998d21d643c",
      "crc32": "4db3022d",
      "sha1": "abceccfc74a577ed06a5aeb7bebe365e9ff8946d"
    }
  ],
  "files_count": 13,
  "item_size": 10682344,
  "metadata": {
    "mediatype": "texts",
    "collection": ["opensource", "community"],
    "title": "Example title"
  },
  "server": "ia800308.us.archive.org",
  "workable_servers": ["ia800308.us.archive.org", "ia600308.us.archive.org"]
}
```

Current compatibility notes:

- Full metadata responses return item-level fields directly at the top level.
- Top-level fields like `d1`, `d2`, `dir`, `server`, `workable_servers`, `files_count`, `item_size`, and `item_last_updated` are useful operational hints but not all fields are guaranteed on every item.
- The authoritative file list usually appears in `files`; item-level descriptive metadata is under `metadata`.
- Many numeric-looking values are strings in the file list (`size`, `mtime`) and should be parsed defensively.
- `_meta.xml` and `_files.xml` are still the canonical metadata files in the item directory; `/metadata/{identifier}` is the JSON access layer over that information.

### 4.2 Partial metadata request

Endpoint pattern:

```http
GET https://archive.org/metadata/{identifier}/{field}
```

Examples:

```http
GET https://archive.org/metadata/xfetch/server
GET https://archive.org/metadata/xfetch/files/0
GET https://archive.org/metadata/xfetch/metadata
```

For large arrays, support slicing:

```http
GET https://archive.org/metadata/{identifier}/files?start=100&count=5
```

Important response-shape difference:

- Full metadata reads return the object itself.
- Partial metadata reads return an object with a `result` field.

Example:

```json
{
  "result": "ia800308.us.archive.org"
}
```

Implementation rule:

```python
def unwrap_partial_metadata(data: dict):
    if "error" in data:
        raise MetadataAPIError(data["error"], data.get("errcode"))
    if "result" not in data:
        raise MetadataAPIError("partial metadata response missing result")
    return data["result"]
```

### 4.3 Error behavior

The legacy behavior is inconsistent:

- missing item on full `/metadata/{identifier}` may return an empty array
- partial reads may return an `error`
- some errors return an `error` field

Use:

```http
GET https://archive.org/metadata/{identifier}?extended_err=1
```

when you want machine-parsable error behavior.

Current note: extended errors are documented as a newer compatibility-preserving option. When enabled, some errors include an integer `errcode` along with `error`. Do not assume every error has `errcode`.

Implementation rule:

```python
if response.status_code != 200:
    raise HTTPError

data = response.json()

if data == []:
    raise ItemNotFound

if isinstance(data, dict) and "error" in data:
    raise MetadataAPIError(data["error"], data.get("errcode"))
```

Recommended parser split:

```python
def parse_full_metadata_response(identifier: str, data):
    if data == []:
        raise ItemNotFound(identifier)
    if isinstance(data, dict) and "error" in data:
        raise MetadataAPIError(data["error"], data.get("errcode"))
    if not isinstance(data, dict):
        raise MetadataAPIError(f"unexpected metadata response for {identifier}")
    return data
```

## 5. Advanced Search API

### 5.1 Purpose

Use Advanced Search for discovery:

- find items in a collection
- find collections
- search by metadata fields
- enumerate identifiers
- filter by media type
- sort by dates, title, downloads, etc.

Advanced Search is not the authoritative manifest. After discovering identifiers, always fetch `/metadata/{identifier}`.

### 5.2 Endpoint

```http
GET https://archive.org/advancedsearch.php
```

Typical parameters:

| Parameter | Meaning |
|---|---|
| `q` | query string |
| `fl[]` | fields to return |
| `rows` | number of rows per page |
| `page` | page number |
| `sort[]` | sort expression |
| `output=json` | JSON output |

Practical parameter notes:

- Prefer explicit `fl[]` field lists. If you omit fields, response payloads and behavior can be less predictable for crawler use.
- Keep `rows` conservative. `100` is safe for interactive checks; `500`-`1000` is a reasonable crawler range when you have backoff and checkpointing.
- Use stable sorting only for small result sets. For large result sets, switch to Scrape API.
- Treat `responseHeader.status != 0` or a top-level `error` as an API failure, even if HTTP status is `200`.

Example:

```text
https://archive.org/advancedsearch.php?q=collection:software&fl[]=identifier&fl[]=title&fl[]=mediatype&rows=100&page=1&output=json
```

### 5.3 Response shape

Typical response:

```json
{
  "responseHeader": {
    "status": 0
  },
  "response": {
    "numFound": 12345,
    "start": 0,
    "docs": [
      {
        "identifier": "example-item",
        "title": "Example Item",
        "mediatype": "software"
      }
    ]
  }
}
```

### 5.4 Enumerating identifiers with page-based search

Pseudo-code:

```python
page = 1
rows = 100
while True:
    result = advanced_search(
        query="collection:software",
        fields=["identifier"],
        rows=rows,
        page=page,
    )

    docs = result["response"]["docs"]
    if not docs:
        break

    for doc in docs:
        yield doc["identifier"]

    page += 1
```

### 5.5 Important limitation

Advanced Search has a deep paging limitation. Sorted paged results are limited to the first 10,000 returnable results.

For large enumerations, implement the **Scrape API** cursor approach instead of relying only on `page`.

## 6. Scrape API for Large Enumeration

Internet Archive's search documentation describes a cursor-based Scrape API for deep enumeration.

Verified current endpoint:

```text
https://archive.org/services/search/v1/scrape
```

Use this when:
- result sets may exceed 10,000
- you need stable deep crawling
- you are building a large preservation index

Implementation concept:

```python
SCRAPE_ENDPOINT = "https://archive.org/services/search/v1/scrape"

params = {
    "q": "collection:software",
    "fields": "identifier,title,mediatype,collection",
    "count": 1000,
}

cursor = None

while True:
    if cursor:
        params["cursor"] = cursor

    result = requests.get(SCRAPE_ENDPOINT, params=params, headers=headers).json()

    for item in result.get("items", []):
        yield item

    cursor = result.get("cursor")
    if not cursor:
        break
```

Current parameters:

| Parameter | Meaning |
|---|---|
| `q` | Lucene-like query, same general query language as Advanced Search |
| `fields` | comma-delimited metadata fields to return |
| `sorts` | comma-delimited sort fields; if `identifier` is specified, it must be last |
| `count` | number of results to return; IA docs state minimum `100` |
| `cursor` | opaque cursor returned by prior response |
| `total_only` | when true, return only the count/total summary |

Current response shape:

```json
{
  "items": [
    {
      "identifier": "example",
      "title": "Example"
    }
  ],
  "total": 198879,
  "count": 100,
  "cursor": "opaque-cursor"
}
```

Important current IA warning: IA explicitly says there is no absolute guarantee that every item will be returned or will remain available during a scraping loop because additions and deletions happen continuously. Store checkpoints and make crawls restartable.

Recommended count:

- Use `count=100` for first tests.
- Use `count=1000` for normal crawls.
- Only raise above that after measuring 429/5xx rates and memory use.
- Do not assume counts over 9999 are portable, even if a third-party wrapper allows them.

Recommended abstraction:

```python
class IdentifierEnumerator:
    def enumerate(self, query: str) -> Iterator[str]:
        ...
```

Then add a second implementation:

```python
class ScrapeAPIEnumerator(IdentifierEnumerator):
    ...
```

For new production crawlers, implement Scrape API first, then keep Advanced Search as a small-result/fallback backend.

## 7. Collection Handling

### 7.1 Collection membership

Items declare collection membership in metadata:

```json
{
  "metadata": {
    "collection": [
      "software",
      "opensource"
    ]
  }
}
```

This means the item belongs to both collections.

Implementation rule: store collection memberships as a many-to-many relation.

Current IA notes:

- All items must belong to at least one collection.
- A collection is itself an item with special characteristics.
- Current developer docs say collection creation is IA-staff controlled.
- Collection metadata is not a reliable tree. Use graph traversal with cycle detection.

Relational schema:

```sql
CREATE TABLE ia_items (
    identifier TEXT PRIMARY KEY,
    mediatype TEXT,
    title TEXT,
    publicdate TEXT,
    addeddate TEXT,
    item_last_updated INTEGER,
    item_size INTEGER,
    files_count INTEGER,
    raw_metadata_json TEXT NOT NULL
);

CREATE TABLE ia_collections (
    identifier TEXT PRIMARY KEY,
    title TEXT,
    raw_metadata_json TEXT
);

CREATE TABLE ia_item_collections (
    item_identifier TEXT NOT NULL,
    collection_identifier TEXT NOT NULL,
    PRIMARY KEY (item_identifier, collection_identifier),
    FOREIGN KEY (item_identifier) REFERENCES ia_items(identifier),
    FOREIGN KEY (collection_identifier) REFERENCES ia_collections(identifier)
);
```

### 7.2 Finding items inside a collection

Use a search query:

```text
collection:<collection_identifier>
```

Example:

```text
collection:software
```

Advanced Search URL:

```text
https://archive.org/advancedsearch.php?q=collection:software&fl[]=identifier&fl[]=title&fl[]=mediatype&fl[]=collection&rows=100&page=1&output=json
```

### 7.3 Finding collection items

Search for collection media type:

```text
mediatype:collection
```

Collections inside another collection:

```text
collection:software AND mediatype:collection
```

### 7.4 Recursing collections

Because collections can contain collection items, implement optional recursive traversal.

Pseudo-code:

```python
def crawl_collection(collection_id, recursive=True):
    for doc in search(f"collection:{collection_id}", fields=["identifier", "mediatype"]):
        yield doc

        if recursive and doc.get("mediatype") == "collection":
            yield from crawl_collection(doc["identifier"], recursive=True)
```

Required guardrails:

- maintain a `visited_collections` set
- maintain a `seen_items` set
- avoid infinite loops
- do not assume a single parent
- do not assume collection membership is complete or clean
- set a maximum recursion depth for operator safety, even with `visited_collections`

## 8. Downloading Files

### 8.1 Direct file URL

Canonical download URL:

```text
https://archive.org/download/{identifier}/{filename}
```

Important: `filename` may contain spaces, `#`, `?`, non-ASCII characters, and subdirectory paths. Always URL-encode the path component safely.

Python example:

```python
from urllib.parse import quote

def file_url(identifier: str, filename: str) -> str:
    return f"https://archive.org/download/{quote(identifier)}/{quote(filename, safe='/')}"
```

Safer implementation:

```python
from urllib.parse import quote

def identifier_url_part(identifier: str) -> str:
    # IA identifiers should not contain '/', but quote defensively anyway.
    return quote(identifier, safe="")

def filename_url_part(filename: str) -> str:
    # Keep path separators inside item directories; encode spaces, #, ?, etc.
    return quote(filename, safe="/")

def file_url(identifier: str, filename: str) -> str:
    return (
        "https://archive.org/download/"
        f"{identifier_url_part(identifier)}/{filename_url_part(filename)}"
    )
```

Filesystem note: never write `ia_file.name` directly to disk without local path sanitation. IA file names may contain nested paths, very long names, reserved Windows names, or characters that are legal in IA paths but awkward locally.

### 8.2 Which files to download

Each file entry contains metadata:

```json
{
  "name": "example.zip",
  "source": "original",
  "format": "ZIP",
  "size": "123456",
  "md5": "...",
  "sha1": "...",
  "crc32": "..."
}
```

Useful filters:

```python
def is_original_file(file):
    return file.get("source") == "original"

def is_metadata_file(file):
    return file.get("format") == "Metadata" or file["name"].endswith(("_meta.xml", "_files.xml"))

def should_download(file):
    return is_original_file(file)
```

For preservation crawls, usually store all metadata files even if you skip derivative payloads.

UFID-specific note: for a UFID ingestion pipeline, store the IA file-level checksums as external metadata, but still compute local hashes from downloaded bytes. IA metadata can be stale or absent; UFID identity should come from the actual bytes you ingest.

### 8.3 Resume and integrity

Implement:

- streaming downloads
- temporary `.part` files
- resume via HTTP Range where supported
- checksum validation after download
- retry with exponential backoff
- respect `429` and `Retry-After`

Checksum priority:

1. `sha1`
2. `md5`
3. `crc32`

Do not treat missing checksums as fatal; derived files and some legacy files may lack complete fixity data.

CRC32 implementation note:

```python
import zlib

def crc32_file(path: Path) -> str:
    value = 0
    with path.open("rb") as f:
        for chunk in iter(lambda: f.read(1024 * 1024), b""):
            value = zlib.crc32(chunk, value)
    return f"{value & 0xffffffff:08x}"
```

Download HTTP notes:

- Use `HEAD` only as an optimization. Some IA paths may behave differently across redirects; always fall back to `GET`.
- Preserve the stable archival URL in your database, not the final redirected storage-node URL.
- For resuming, use `Range` against the archival URL and let redirects resolve naturally.
- If a server ignores `Range`, restart from byte zero rather than appending corruptly.

## 10. Automated Access Requirements

All automated requests must use a descriptive `User-Agent`.

Example:

```text
YourTool/0.1.0 (gpt-5.5; contact: you@example.com; purpose: preservation-indexing)
```

Current IA requirements:

- Include the tool or bot name.
- Include a version number.
- For AI agents, identify the model being used when applicable.
- For direct HTTP requests, set the header yourself.
- For the `ia` CLI/Python library, use `user_agent_suffix` rather than replacing the whole default User-Agent.

For direct HTTP:

```python
headers = {
    "User-Agent": "YourTool/0.1.0 (gpt-5.5; contact: you@example.com; purpose: preservation-indexing)",
    "Accept-Encoding": "gzip, deflate",
}
```

Respect:

- delays between bulk requests
- `429 Too Many Requests`
- `Retry-After`
- bounded concurrency
- local caching
- backoff on transient failures

Default conservative settings:

```yaml
metadata_concurrency: 2
download_concurrency: 2
search_delay_seconds: 1.0
metadata_delay_seconds: 0.25
download_delay_seconds: 0.5
max_retries: 5
```

IA's current bot guidance also recommends caching responses, using bulk endpoints, and handling errors gracefully with exponential backoff. Treat these as release requirements, not nice-to-haves.

For UFID-scale ingestion, add:

```yaml
metadata_cache_ttl_hours: 24
respect_retry_after: true
stop_on_repeated_403: true
stop_on_repeated_checksum_mismatch: true
max_download_bytes_per_item: configurable
```

### 11.3 HTTP client

```python
import time
import requests
from requests.adapters import HTTPAdapter
from urllib3.util.retry import Retry

class IAHTTPClient:
    def __init__(self, user_agent: str, timeout: int = 60):
        self.timeout = timeout
        self.session = requests.Session()
        self.session.headers.update({
            "User-Agent": user_agent,
            "Accept-Encoding": "gzip, deflate",
        })

        retry = Retry(
            total=5,
            connect=5,
            read=5,
            status=5,
            backoff_factor=1.5,
            status_forcelist=(429, 500, 502, 503, 504),
            respect_retry_after_header=True,
            allowed_methods=("GET", "HEAD"),
        )

        adapter = HTTPAdapter(max_retries=retry, pool_connections=10, pool_maxsize=10)
        self.session.mount("https://", adapter)

    def get_json(self, url: str, params: dict | None = None) -> dict:
        r = self.session.get(url, params=params, timeout=self.timeout)
        r.raise_for_status()
        try:
            data = r.json()
        except ValueError as exc:
            raise RuntimeError(f"Invalid JSON from {r.url}") from exc
        if isinstance(data, dict):
            return data
        raise RuntimeError(f"Expected JSON object from {r.url}, got {type(data).__name__}")
```

For `/metadata/{identifier}`, use a method that allows `list` because missing full metadata can legitimately return `[]`:

```python
    def get_json_any(self, url: str, params: dict | None = None):
        r = self.session.get(url, params=params, timeout=self.timeout)
        r.raise_for_status()
        try:
            return r.json()
        except ValueError as exc:
            raise RuntimeError(f"Invalid JSON from {r.url}") from exc
```

### 11.4 Advanced Search implementation

```python
class AdvancedSearchClient:
    ENDPOINT = "https://archive.org/advancedsearch.php"

    def __init__(self, http: IAHTTPClient):
        self.http = http

    def search_page(
        self,
        query: str,
        fields: list[str] | None = None,
        rows: int = 100,
        page: int = 1,
        sorts: list[str] | None = None,
    ) -> dict:
        params = {
            "q": query,
            "rows": rows,
            "page": page,
            "output": "json",
        }

        for field in fields or ["identifier"]:
            params.setdefault("fl[]", [])
            params["fl[]"].append(field)

        for sort in sorts or []:
            params.setdefault("sort[]", [])
            params["sort[]"].append(sort)

        return self.http.get_json(self.ENDPOINT, params=params)

    def iter_docs(
        self,
        query: str,
        fields: list[str] | None = None,
        rows: int = 100,
        max_pages: int | None = None,
    ):
        page = 1

        while True:
            if max_pages is not None and page > max_pages:
                break

            data = self.search_page(query, fields=fields, rows=rows, page=page)
            docs = data.get("response", {}).get("docs", [])

            if not docs:
                break

            for doc in docs:
                yield doc

            page += 1
```

### 11.5 Metadata implementation

```python
class MetadataClient:
    ENDPOINT = "https://archive.org/metadata"

    def __init__(self, http: IAHTTPClient):
        self.http = http

    def get_metadata(self, identifier: str) -> dict:
        url = f"{self.ENDPOINT}/{identifier}"
        data = self.http.get_json_any(url, params={"extended_err": "1"})

        if data == []:
            raise LookupError(f"Internet Archive item not found: {identifier}")

        if isinstance(data, dict) and "error" in data:
            raise RuntimeError(f"Metadata API error for {identifier}: {data}")

        return data

    def get_partial(self, identifier: str, pointer: str):
        pointer = pointer.strip("/")
        url = f"{self.ENDPOINT}/{identifier}/{pointer}"
        data = self.http.get_json(url, params={"extended_err": "1"})
        return unwrap_partial_metadata(data)

    def parse_item(self, identifier: str) -> IAItem:
        data = self.get_metadata(identifier)
        md = data.get("metadata", {})

        collection = md.get("collection", [])
        if isinstance(collection, str):
            collections = [collection]
        else:
            collections = list(collection or [])

        files = []
        for f in data.get("files", []):
            if not isinstance(f, dict) or not f.get("name"):
                continue
            files.append(IAFile(
                name=f["name"],
                source=f.get("source"),
                format=f.get("format"),
                size=int(f["size"]) if str(f.get("size", "")).isdigit() else None,
                mtime=int(f["mtime"]) if str(f.get("mtime", "")).isdigit() else None,
                md5=f.get("md5"),
                sha1=f.get("sha1"),
                crc32=f.get("crc32"),
                raw=f,
            ))

        return IAItem(
            identifier=identifier,
            mediatype=md.get("mediatype"),
            title=md.get("title"),
            collections=collections,
            files=files,
            raw=data,
        )
```

### 11.5.1 Scrape API implementation

```python
class ScrapeSearchClient:
    ENDPOINT = "https://archive.org/services/search/v1/scrape"

    def __init__(self, http: IAHTTPClient):
        self.http = http

    def iter_docs(
        self,
        query: str,
        fields: list[str] | None = None,
        count: int = 1000,
        sorts: list[str] | None = None,
    ):
        params = {
            "q": query,
            "fields": ",".join(fields or ["identifier"]),
            "count": max(count, 100),
        }
        if sorts:
            params["sorts"] = ",".join(sorts)

        cursor = None
        while True:
            page_params = dict(params)
            if cursor:
                page_params["cursor"] = cursor

            data = self.http.get_json(self.ENDPOINT, params=page_params)
            items = data.get("items") or []
            if not isinstance(items, list):
                raise RuntimeError(f"Unexpected Scrape API response: {data}")

            for item in items:
                if isinstance(item, dict):
                    yield item

            cursor = data.get("cursor")
            if not cursor:
                break
```

### 11.6 Download implementation

```python
import hashlib
import os
from pathlib import Path
from urllib.parse import quote

class DownloadClient:
    def __init__(self, http: IAHTTPClient):
        self.http = http

    def file_url(self, identifier: str, filename: str) -> str:
        return f"https://archive.org/download/{quote(identifier)}/{quote(filename, safe='/')}"

    def download_file(self, identifier: str, ia_file: IAFile, dest_dir: Path) -> Path:
        dest_dir.mkdir(parents=True, exist_ok=True)
        dest = safe_join(dest_dir, ia_file.name)
        dest.parent.mkdir(parents=True, exist_ok=True)

        tmp = dest.with_suffix(dest.suffix + ".part")
        url = self.file_url(identifier, ia_file.name)

        with self.http.session.get(url, stream=True, timeout=self.http.timeout) as r:
            r.raise_for_status()
            with open(tmp, "wb") as f:
                for chunk in r.iter_content(chunk_size=1024 * 1024):
                    if chunk:
                        f.write(chunk)

        os.replace(tmp, dest)
        self.verify(dest, ia_file)
        return dest

    def verify(self, path: Path, ia_file: IAFile) -> None:
        if ia_file.sha1:
            algo = hashlib.sha1()
            expected = ia_file.sha1.lower()
        elif ia_file.md5:
            algo = hashlib.md5()
            expected = ia_file.md5.lower()
        else:
            return

        with open(path, "rb") as f:
            for chunk in iter(lambda: f.read(1024 * 1024), b""):
                algo.update(chunk)

        actual = algo.hexdigest().lower()
        if actual != expected:
            raise ValueError(f"Checksum mismatch for {path}: expected {expected}, got {actual}")
```

Add a local path guard:

```python
def safe_join(root: Path, archive_name: str) -> Path:
    root = root.resolve()
    parts = [
        part
        for part in archive_name.replace("\\", "/").split("/")
        if part not in ("", ".", "..")
    ]
    if not parts:
        raise ValueError(f"unsafe empty archive path: {archive_name!r}")
    candidate = root.joinpath(*parts).resolve()
    if root != candidate and root not in candidate.parents:
        raise ValueError(f"archive path escapes destination: {archive_name!r}")
    return candidate
```

## 14. Edge Cases Codex Must Handle

### Metadata inconsistencies

- `collection` may be a string or list
- `size` may be stringified integer
- `mtime` may be missing
- `files` may be missing or empty
- checksums may be missing
- item may have no downloadable original files
- item may be dark/restricted/unavailable

### Search inconsistencies

- result set may change during crawl
- same item may appear in multiple collections
- collection recursion may loop
- Advanced Search deep paging may fail beyond 10,000 sorted results
- fields may be absent unless explicitly requested

### Filename/path issues

- spaces
- URL-sensitive characters
- Unicode
- nested paths
- local filesystem reserved names
- very long paths on Windows

### Operational issues

- 429 rate limits
- 5xx errors
- connection resets
- partial downloads
- checksum mismatch
- items moving between IA storage servers
- temporary unavailability
- partial metadata reads returning `{"result": ...}` while full reads return raw objects
- search crawls changing under your feet because IA additions/deletions continue during enumeration
- file metadata checksums disagreeing with downloaded bytes
- redirected download URLs expiring or moving

### Security/path issues

- path traversal in file names if you write IA paths directly to disk
- Windows reserved names such as `CON`, `PRN`, `AUX`, `NUL`, `COM1`, `LPT1`
- filenames ending in spaces or periods on Windows
- HTML/metadata values that must be escaped before display in a web UI
- credentials accidentally stored in logs when using authenticated APIs

## 17. Non-Goals for First Version

Do not implement these initially:

- uploading
- metadata writing
- item deletion
- review APIs
- tasks/catalog APIs
- authentication-only private data access
- Wayback CDX crawling
- privileged Changes API crawling

Add Wayback/CDX later as a separate subsystem. It solves a different problem: archived web capture discovery, not archive.org item/file collection browsing.

Add the privileged Changes API later only if you have IA-approved credentials and a real need for catalog-change tracking.

## 18. Final Design Rule

For archive.org item collections:

```text
Advanced Search / Scrape API discovers identifiers.
Metadata API describes items and files.
Download URLs retrieve files.
Collections are graph metadata, not folders.
Local storage must deduplicate by identifier and file checksum.
```

Additional 2026-safe design rule:

```text
Use Scrape API for deep enumeration.
Use Advanced Search for small discovery and debugging.
Use Metadata API for item/file truth.
Use stable /download archival URLs for retrieval.
Use local byte hashing for UFID identity.
Treat IA-declared checksums as metadata observations, not proof.
```
